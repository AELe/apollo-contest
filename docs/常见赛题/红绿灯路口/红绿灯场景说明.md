### 一、场景回放与赛题分析

**核心需求**：

1. 主车必须在停止线前 **1.5-2.0m** 内精确停车
2. 红灯期间保持静止（不得超出停止线）
3. 绿灯后通过路口时速度不超过 6 m/s

**评判标准**：

| 情况                      | 结果     |
| ------------------------- | -------- |
| 停止位置不在 1.5-2.0 m 内 | 扣 20 分 |
| 超速（每超 1 m/s）        | 扣 20 分 |
| 超出停止线或红灯未停      | 0 分     |

**技术难点**：

- 停车距离精度控制（±0.5 m）
- 交通灯状态实时检测（红/绿灯切换）
- 路口区域速度限制实施
- 多阶段场景切换逻辑

**解决思路**：

1. 修改 `traffic_light` 插件停止距离参数
2. 新增 `region_speed_limit` 限速插件
3. 优化场景切换逻辑（APPROACH → INTERSECTION_CRUISE）

**场景阶段切换原理**：

这段代码是一个交通灯保护阶段（`TrafficLightProtectedStage`）中的交通灯靠近阶段（`TrafficLightProtectedStageApproach`）的处理函数（`Process`）。首先，它遍历当前交通灯重叠区域的 ID 列表，并检查每个交通灯的颜色是否为绿灯。如果存在任何一个交通灯不是绿灯，那么设置变量 `traffic_light_all_done` 为 `false`，然后退出循环。否则，将变量 `traffic_light_all_done` 设置为 `true`。

如果所有交通灯都是绿灯，那么函数调用 `FinishStage()` 来结束该阶段，然后返回 `Stage::FINISHED` 状态。否则，返回 `Stage::RUNNING` 状态，表示该阶段仍在运行中。

路径：`planning/scenarios/traffic_light/protected/stage_approach.cc`

```cpp
StageResult TrafficLightProtectedStageApproach::Process(
    const TrajectoryPoint& planning_init_point, Frame* frame) {
  // `traffic_light_all_done` 用于标记是否所有交通信号灯都已处理完毕
  bool traffic_light_all_done = true;

  // 遍历当前交通信号灯的重叠区域
  for (const auto& traffic_light_overlap_id :
       context->current_traffic_light_overlap_ids) {
    // 获取交通信号灯在参考线上的重叠信息
    PathOverlap* current_traffic_light_overlap =
        reference_line_info.GetOverlapOnReferenceLine(
            traffic_light_overlap_id, ReferenceLineInfo::SIGNAL);
    if (!current_traffic_light_overlap) {
      continue;
    }

    // 设置交通信号灯不具备交通优先权
    reference_line_info.SetJunctionRightOfWay(
        current_traffic_light_overlap->start_s, false);

    // 获取车辆前沿位置相对于交通信号灯停车线的距离
    const double adc_front_edge_s = reference_line_info.AdcSlBoundary().end_s();
    const double distance_adc_to_stop_line =
        current_traffic_light_overlap->start_s - adc_front_edge_s;
    auto signal_color = frame->GetSignal(traffic_light_overlap_id).color();

    // 检查车辆到停车线的距离是否小于最大有效停车距离
    if (distance_adc_to_stop_line > scenario_config.max_valid_stop_distance()) {
      traffic_light_all_done = false;
      break;
    }

    // 检查交通信号灯的颜色是否为绿色
    if (signal_color != TrafficLight::GREEN) {
      traffic_light_all_done = false;
      break;
    }
  }

  // 如果所有交通信号灯都已经处理完毕，则返回 `FinishStage()` 表示阶段已完成
  if (traffic_light_all_done) {
    return FinishStage();
  }

  // 否则，返回 `result.SetStageStatus(StageStatusType::RUNNING)` 表示阶段仍在运行中
  return result.SetStageStatus(StageStatusType::RUNNING);
}
```

**进入 `INTERSECTION_CRUISE` 的 stage 定义：**

这段代码是交通灯保护阶段（`TrafficLightProtectedStage`）中的交通灯保护交叉路口阶段（`TrafficLightProtectedStageIntersectionCruise`）的处理函数（`Process`）。首先，它调用 `stage_impl_.CheckDone()` 函数，检查是否已经通过了交叉路口。如果已经通过了交叉路口，那么将返回 `true`，表示该阶段已经完成。如果该阶段已经完成，那么函数调用 `FinishStage()` 来结束该阶段，然后返回 `Stage::FINISHED` 状态。否则，返回 `Stage::RUNNING` 状态，表示该阶段仍在运行中。

路径：`planning/scenarios/traffic_light/protected/stage_intersection_cruise.cc`

```cpp
StageResult TrafficLightProtectedStageIntersectionCruise::Process(
    const common::TrajectoryPoint& planning_init_point, Frame* frame) {
  bool stage_done = CheckDone(*frame, injector_->planning_context(), true);
  // 定义交叉路口
  if (stage_done) {
    // 如果通过交叉路口
    return FinishStage();
    // `INTERSECTION_CRUISE` 的 stage 完成
  }
  return result.SetStageStatus(StageStatusType::RUNNING);

  // 进入 `INTERSECTION_CRUISE` 的 `RUNNING`
}
```

该函数调用 `FinishScenario()` 函数，结束整个交通灯保护阶段（`TrafficLightProtectedStage`），并返回 `Stage::FINISHED` 状态，表示该阶段已经完成。

```cpp
StageResult TrafficLightProtectedStageIntersectionCruise::FinishStage() {
  return FinishScenario();
  // `INTERSECTION_CRUISE` 的 stage 完成
}
```

### 三、解题方法

#### 1. 代码调参

**初始化配置文件**：

```bash
buildtool profile config init --package planning-traffic-rules-traffic-light --profile=default
aem profile use default
```

**修改停止距离**：

```diff
# traffic_light/conf/default_conf.pb.txt
- stop_distance: 1.0
+ stop_distance: 1.7  # 取 1.5-2.0 m 中间值
```

**配置限速插件**：

注：本教程 traffic_rules 插件形式

配置修改：

- **路径**：`region_speed_limit/conf/default_conf.pb.txt`

- **推荐参数**：

    ```text
    forward_buffer: 3.0
    backward_buffer: 2.0
    limit_speed: 6.0  # 符合≤6m/s要求
    ```

- **插件注册**：

    ```text
    # traffic_rule_config.pb.txt
    rule {
      name: "REGION_SPEED_LIMIT"
      type: "RegionSpeedLimit"
    }
    ```

- **调参原则**：

    | 参数          | 调整方向 | 效果         |
    | ------------- | -------- | ------------ |
    | stop_distance | +0.1 m   | 增大停车距离 |
    | stop_distance | -0.1 m   | 减小停车距离 |
    | limit_speed   | ≤6.0     | 确保不超速   |

#### 2. 场景调试过程

**操作流程**：

1. 启动 DreamView：`aem bootstrap start --plus`

2. 修改配置文件：

    ```bash
    vim profiles/default/modules/planning/traffic_rules/traffic_light/conf/default_conf.pb.txt
    vim profiles/default/modules/planning/conf/traffic_rule_config.pb.txt  # 添加并生效限速插件
    vim profiles/default/modules/planning/traffic_rules/region_speed_limit/conf/default_conf.pb.txt
    ```

3. 重启模块：DreamView → Planning 模块

4. 测试验证：

   - 验证停车位置（1.5-2.0 m）
   - 检查绿灯后通过速度（≤6 m/s）
   - 查看运行日志：`grep 'traffic_light' /apollo/data/log/planning.INFO`

**问题解决方法**：

| 问题现象        | 解决方案                               |
| --------------- | -------------------------------------- |
| 停止距离 >2.0 m | 减小 `stop_distance` 值（每次 -0.1 m） |
| 停止距离 <1.5 m | 增大 `stop_distance` 值（每次 +0.1 m） |
| 通过速度 >6 m/s | 检查 `limit_speed` 是否 ≤6.0           |
| 未触发限速      | 确认插件注册配置                       |

**最终验证指标**：

1. 停止位置：1.7±0.2 m
2. 通过速度：≤6.0 m/s
3. 场景得分：≥80 分

### 关键修改总结

1. **停车精度**：通过 `stop_distance:1.7` 实现 1.5-2.0 m 停车要求
2. **速度控制**：新增 `region_speed_limit` 插件设置 `limit_speed:6.0`
3. **场景完整性**：
   - 5 m 处进入 `TRAFFIC_LIGHT_PROTECTED` 场景
   - `APPROACH` 阶段完成红灯停车
   - `INTERSECTION_CRUISE` 阶段执行限速通过
